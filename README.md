# OrangeOS v1.0

> 一个基于 x86 架构，从 BootLoader 开始自主实现的教学型操作系统\
> Inspired by 《Orange'S：一个操作系统的实现》

------------------------------------------------------------------------

# 1. 项目简介

OrangeOS 是一个从零实现的小型操作系统项目。

项目目标：

-   理解计算机启动流程
-   掌握 BootLoader、Kernel、Interrupt、Process 等操作系统核心机制
-   实现一个具有 Shell、文件系统、多任务能力的微型 OS
-   在基础 OS 功能之上扩展具有展示性的特色模块

最终系统目标：

    BIOS
     |
    Boot Sector
     |
    Boot Loader
     |
    Kernel
     |
    User Interface

# 11. Ring 3 用户态

当前已建立内核 GDT、32 位 TSS、独立特权级中断栈，以及三个仅标记为用户可访问的
代码/数据/栈页面。Shell 命令：

    user

会进入 CPL3，通过 `int 0x80` 获取 ticks、空闲页和 PID，再通过受控 `SYS_EXIT`
返回 Shell。

验证：

    make test-ring3

独立用户进程命令：

    run       启动调度器管理的 PID 4 用户进程
    ps        查看 PID 4 状态和累计运行 tick
    kill 4    终止 PID 4

PID 4 在 Ring 3 运行约五秒后调用 `SYS_EXIT`，调度器将其标记为 `EXITED` 并恢复其他任务。
自动生命周期验证：

    make test-process

用户态异常隔离：

    runfault   让 PID 4 在 Ring 3 访问未映射页面
    ps         查看 FAULTED 状态、CR2 和页故障错误码

Ring 3 页故障只终止 PID 4；Ring 0 页故障仍会保护性停机。自动验证：

    make test-userfault

用户进程的代码、数据和栈页现在按运行动态分配，并在正常退出、页故障或 `kill 4`
时解除映射和归还。验证运行中增加三页、退出后恢复基线：

    make test-resources

OrangeFS 用户程序采用 `OEX2:EE:LL:CC:<hex machine code>` 格式，其中包含入口偏移、
代码长度和 8 位校验和。可通过以下命令加载到
动态用户代码页并作为 PID 4 执行：

    exec demo.oex
    ps

默认 `demo.oex` 设置退出结果 42，`ps` 应显示 `code=42`。自动验证：

    make test-exec

损坏格式验证：

    exec bad.oex

应返回 `Invalid OEX2 executable`，且不会启动用户进程。

# 12. OrangeFS v3

ORF3 将目录与数据分离：LBA 42 保存目录，后续为 7 个双扇区文件 extent。
单文件容量由 63 字符提升到 1023 字节，并新增：

    stat <file>

跨扇区默认文件：

    stat big.txt

预期显示 `size=700 bytes start=53 sectors=2`。自动验证同时检查偏移 511/512
两侧的数据：

    make test-fs-large

------------------------------------------------------------------------

# 13. OrangeFS v4 位图分配

ORF4 在目录中加入 32 位数据扇区位图。`touch` 动态分配两个连续扇区，`rm`
归还位图，后续文件会复用已释放的 extent。

    disk
    touch temp
    disk
    rm temp
    disk

空闲扇区应呈现 `20 -> 18 -> 20`。自动验证：

    make test-fs-bitmap

------------------------------------------------------------------------

# 14. OrangeFS v5 可变 extent

ORF5 按实际内容分配空间：`touch` 只建立目录项，不占数据扇区；写入不超过
512 字节时分配 1 个扇区，超过 512 字节时分配 2 个连续扇区。文件长度跨过
512 字节边界时会重新分配 extent，`rm` 会按实际扇区数归还位图。

默认 6 个文件共使用 7 个扇区，因此启动后 `disk` 显示 `free=25/32`。

    disk
    touch temp
    disk
    write temp hi
    disk
    rm temp
    disk

预期空闲扇区变化为 `25 -> 25 -> 24 -> 25`。自动验证：

    make test-fs-large
    make test-fs-bitmap

------------------------------------------------------------------------

# 15. OrangeFS v6 目录校验

ORF6 在目录扇区末尾保存 XOR 校验值。每次创建、写入或删除文件后，系统会先
重新计算校验值，再把完整目录扇区写入磁盘。启动时同时验证 `ORF6` 魔数和整个
目录扇区；如果元数据被破坏，当前版本会重新建立默认文件系统，避免继续使用
错误的位图或 extent。

故障注入测试会复制磁盘镜像、篡改 LBA 42 的位图字节，然后重新启动验证恢复：

    make test-fs-checksum

------------------------------------------------------------------------

# 16. OrangeFS v7 双目录恢复

ORF7 保留两份带校验和版本号的目录：主目录位于 LBA 42，备份目录位于
LBA 75。每次目录更新时版本号递增，并按“备份优先、主目录随后”的顺序写入。
启动时分别验证两份目录，选择校验有效且版本较新的副本，再同步修复另一份。

`make test-fs-checksum` 现在还会先创建并写入用户文件 `keep`，再从宿主机破坏
主目录。重启后必须仍能读出 `survives`，并保持 `free=24/32`，证明恢复没有
重新格式化或丢失用户目录项。

------------------------------------------------------------------------

# 17. OrangeFS v8 文件数据校验

ORF8 使用目录项最后两个字节保存文件内容的 16 位加法校验。默认文件格式化和
每次 `write` 后都会更新校验；`cat` 与 `exec` 读取数据后必须先通过校验，否则
返回 `File data corrupt`，损坏的 OEX 程序不会进入 Ring3。

故障注入验证：

    make test-fs-data-checksum

成为一个具有完整结构和展示价值的小型操作系统。
