# OrangeOS Day16 开发日志

## 今日目标

为后续 Ring 3、用户程序和进程隔离开发建立可自动重复的启动回归基线。

## 完成内容

### 1. QEMU 调试输出

- `print_string32` 在写入 VGA 文本显存的同时，将字符镜像到调试端口 `0xE9`。
- 真机运行路径不依赖该端口；QEMU/Bochs 可用它采集早期启动日志。
- 屏幕输出和现有 Shell 行为保持不变。

### 2. 自动启动冒烟测试

新增：

```bash
make test
```

该目标会：

1. 构建完整软盘镜像；
2. 使用 QEMU 无界面、快照模式启动三秒；
3. 捕获 `0xE9` 调试输出；
4. 检查 Kernel 启动标志和 Shell 提示符；
5. 任一标志缺失即返回失败。

成功结果：

```text
OrangeOS boot smoke test passed
```

测试使用 `-snapshot`，不会修改 OrangeFS 持久化数据。

## 下一阶段：正式用户态

Ring 3 不能只增加用户代码段后直接 `iret`。当前分页恒等映射均为 supervisor 页面，正式实现还需要形成以下闭环：

- 内核自有 GDT，以及 Ring 3 code/data 描述符；
- TSS 与可靠的 `SS0:ESP0` 中断栈；
- 仅对用户代码、用户数据和用户栈设置页表 `U/S` 权限；
- 用户指针校验和受控的系统调用 ABI；
- 用户进程退出后回收页、栈和 PCB；
- 对用户态非法访存执行进程终止，而不是停止整个内核；
- 为上述路径扩展自动测试。

这组约束保证下一阶段实现的是有边界的用户态，而不是让 Ring 3 直接访问全部内核内存。
